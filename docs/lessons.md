# 해 보면서 배운 것

직접 실험하거나 비슷한 도구를 만드는 사람을 위한 교훈이에요. 결과 숫자는 [실험 기록](records/README.md)에 있어요.

## 벤치 설계

- **커밋 메시지를 요청으로 쓰면 안 돼요.** 너무 짧아서 할 일을 모르거나, 너무 자세해서 정답을 알려줘요. 게다가 정답이 커밋 작성자의 구현 하나에 묶여요. 구현 전에 쓰인 요청(이슈, 티켓, PR 설명)을 쓰세요.
- **누락은 에이전트 자신의 구현 기준으로 판정해요.** 커밋 메시지 요청에서는 에이전트가 다르게 구현해서 "놓친" 파일의 절반 이상이 실제로는 필요 없었어요. 판정자(모델)에게 에이전트의 diff와 원래 diff를 함께 주고, 빠진 파일이 여전히 필요한지 묻게 했어요 (`bench/judge-misses.mts`).
- **"범위를 모두 찾아라"라고 시키면 순정에 가장 유리해요.** 실제 사용자는 "이거 해 줘"라고만 해요. 요청을 주고 변경까지 하게 한 뒤 최종 diff로 채점하는 현실형 벤치를 주 벤치로 삼으세요.
- **한 번 실행은 편차가 커요.** 같은 순정도 케이스 하나에서 4/4와 2/4가 나오고, 비용은 2~3배 달라요. "순정이 놓친 곳"도 한 번 실행으로 정하면 다른 비교군에 유리하게 기울어요.
- **튜닝한 케이스와 판정할 케이스를 나눠요.** holdout은 스펙을 고정한 뒤에만 돌리고, 튜닝 중에는 놓친 내용을 보지 않아요. 규칙도 dev 피드백을 받기 전 버전으로 판정했어요.
- **미래가 새지 않게 해요.** 케이스 스냅샷에는 기록을 넣지 않았어요. setup은 모든 케이스보다 앞선 시점, 기록을 자른 사본, 원격 없음, GitHub 차단, 도구 호출 감사 조건에서 돌렸어요.
- **정답에서 노이즈를 빼요.** 한 커밋에 섞인 무관한 변경, AUTHORS 같은 파일은 필수/선택 라벨로 걸러요. 라벨은 비교군 결과를 모르는 서브에이전트가 diff만 보고 붙였어요.
- **seed는 정확한 diff로 만들어요.** 공백 무시 diff(`-w`)로 만들면 들여쓰기만 바뀐 줄이 빠져서 문법이 깨진 파일이 생겨요. 적용 후 문법 검사를 하세요.

## 에이전트와 지시문

- **지시는 긍정형으로 써요.** "X 하지 마라"보다 "Y 한다"로 써요. 측정한 결과가 아니라 이 레포의 작성 원칙이에요.
- **필수로 시킨 도구 사용은 탐색을 대신해 버려요.** Jev 스캔을 필수로 하자 작은 모델이 직접 찾기를 덜 했고, 필수 파일을 잃었어요.
- **skill은 설명(description)으로 불려요.** 실제 요청에 나오는 말("implement", "fix", "rename", "deprecate" 등)로 쓰고, 항상 읽히는 지침에서도 가리켜야 불렸어요.
- **harness 동작을 강제로 묶지 마세요.** 특정 서브에이전트만 쓰게 권한을 고정하는 식은 그 harness 전용 구현이 돼요. 스펙은 무엇을, 왜만 말하고, 벗어난 사용은 스펙을 고칠 발견으로 다뤄요.
- **작은 모델이 쓴 검색 질문은 이미 아는 곳을 확인하는 데 그쳐요.** "이 파일이 무슨 주제인가" 같은 질문이 나왔어요. 넓은 질문(변경 설명 전체)을 넓은 범위에 던지는 게 순위 도구로는 나았어요.
- **작은 모델은 가끔 구조화된 출력 없이 끝나요** (비교군당 약 1/16). 실패로 세고 다시 돌려요.

## Jev

- 요청 하나에 질문을 여러 개 넣을 수 있고, 질문 하나마다 약 17토큰만 더 들어요. 같은 조각에 대한 질문은 묶어야 해요.
- 조각 하나만 보고 답하므로, 질문도 조각 하나만으로 답할 수 있어야 해요.
- "변경 전에는 없는 문구"를 물으면 못 찾아요. "추가해야 할 위치인가"를 묻는 질문이 필요해요(예: "다음 릴리스의 릴리스 노트인가").
- 에이전트가 스캔 범위를 정하게 두면 요청이 실행당 수천 건까지 불어날 수 있어요. 좁게 먼저, 묶어서.

## 환경 (Claude Code, Windows)

- `core.symlinks=false`에서는 심볼릭 링크가 경로 글자만 든 파일로 풀려요. `CLAUDE.md`가 `AGENTS.md`를 가리키는 링크인 레포(outline)는 지침이 로드되지 않았어요.
- 이름에 `:`가 든 파일은 Windows에서 만들 수 없어요. 스냅샷에서 경고와 함께 건너뛰었어요.
- blobless 클론에서 오래된 커밋을 checkout하면 blob을 하나씩 가져와서 몇 시간이 걸려요. 기준 커밋을 `fetch --depth=1`로 받으면 몇 초예요.
- `.claude/`는 보호 경로라 dontAsk 모드에서 Write와 Bash 모두 막혀요. setup은 bypass 모드에 차단 목록(홈, GitHub)과 기록 검사를 붙여 돌렸어요. bypass에서도 deny 규칙은 적용돼요.
- `total_cost_usd`에는 서브에이전트가 포함되지만, `duration_ms`에는 서브에이전트 시간이 빠져요. 시간은 실제 경과 시간으로 재요.
- `--setting-sources project`로도 사용자 동기화 skill은 로드돼요. 비교군을 깨끗하게 하려면 `--disable-slash-commands`를 써요.
